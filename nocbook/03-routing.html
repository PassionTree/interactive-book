라우팅: 길을 고르는 법

토폴로지가 도로망이라면 라우팅은 내비게이션입니다. 가장 단순한 내비게이션은 "항상 같은 길"을 알려 주고, 똑똑한 내비게이션은 막히는 길을 피해 갑니다. 하지만 칩 안에서는 똑똑함에 대가가 따릅니다. 잘못 고른 길들이 서로 꼬리를 물면 네트워크 전체가 멈추는 데드락이 생기기 때문입니다.

라우팅 알고리즘의 분류

라우팅 알고리즘은 경로 선택에 무엇을 고려하느냐에 따라 세 가지로 나뉩니다.

또 다른 축으로 최소(minimal) 라우팅은 항상 최단 경로만 쓰고, 비최소(non-minimal) 라우팅은 부하 분산이나 고장 회피를 위해 돌아가기도 합니다. 그리고 경로를 출발지 NI가 패킷 헤더에 모두 적어 넣는 소스 라우팅과, 각 라우터가 목적지를 보고 다음 홉만 결정하는 분산 라우팅이 있습니다. NoC는 대부분 분산 라우팅을 조합 논리나 작은 테이블로 구현합니다.

차원 순서 라우팅 (XY)

XY 라우팅은 먼저 X 좌표를 맞춘 뒤 Y 좌표를 맞춥니다. 각 라우터에서 필요한 연산은 좌표 비교 두 번뿐이라 하드웨어가 매우 작고, 아래에서 보듯이 2D Mesh에서 데드락이 원천적으로 불가능합니다. 그래서 상용 NoC의 기본값입니다.

if   (dst.x > cur.x) return EAST;
elif (dst.x < cur.x) return WEST;
elif (dst.y > cur.y) return SOUTH;   // 화면 좌표: y가 아래로 증가
elif (dst.y < cur.y) return NORTH;
else                 return LOCAL;

단점은 경로 다양성이 0이라는 것입니다. 두 노드 사이에 최단 경로가 수십 개 있어도 XY는 그중 하나만 씁니다. 특정 트래픽 패턴(예: transpose)에서는 일부 링크에 부하가 몰려 처리량이 크게 떨어집니다.

링크의 굵기는 패킷이 그 링크를 지날 확률입니다(적응형은 갈림길마다 균등하게 분배한다고 가정). 클릭으로 출발지와 목적지를 차례로 지정하세요. 오른쪽 아이콘은 알고리즘이 금지하는 회전(빨간 ✕)을 보여줍니다. Odd-Even을 고르면 짝수/홀수 열이 음영으로 표시됩니다.

Turn Model: 회전을 금지해 데드락 막기

2D Mesh에서 패킷이 할 수 있는 회전(turn)은 8가지입니다. 이 8개의 회전은 시계 방향 사이클 4개와 반시계 방향 사이클 4개로 나뉩니다. 만약 네 패킷이 동시에 같은 방향으로 회전하며 서로의 버퍼를 기다리면 순환 대기가 생깁니다 — 데드락입니다(6장에서 직접 만들어 봅니다).

Glass와 Ni(1992)의 Turn model은 "각 사이클에서 회전 하나씩만 금지하면 사이클을 끊을 수 있다"는 아이디어입니다. XY 라우팅은 4개의 회전(Y→X)을 금지해 지나치게 보수적입니다. 2개만 금지해도 데드락을 막을 수 있으며, 남은 6개의 회전을 활용해 적응형 라우팅이 가능합니다. 단, 아무 2개나 금지해서는 안 됩니다. 세 번의 오른쪽 회전은 한 번의 왼쪽 회전과 같기 때문입니다! 아래 실험으로 확인하세요.

검사기는 6×6 Mesh의 모든 채널(방향 링크) 사이에 "이 채널에서 저 채널로 회전이 허용되는가"로 채널 의존성 그래프(CDG)를 만들고, 사이클이 있는지 깊이 우선 탐색으로 찾습니다. 사이클이 발견되면 메시 위에 빨간 경로로 표시됩니다. 비최소 경로까지 포함한 검사이므로 엄격한 기준입니다.

16가지 조합 중 12가지는 데드락이 없고, 대칭성을 고려하면 본질적으로 세 가지 알고리즘으로 정리됩니다.

  • West-First: 서쪽으로 가야 하면 맨 처음에 다 간다. 그 뒤에는 동/남/북 중 적응적으로 선택.
  • North-Last: 북쪽 이동은 마지막에만 한다. 북쪽으로 가기 시작하면 더 이상 회전 불가.
  • Negative-First: 음의 방향(서, 남)을 먼저 다 가고, 그 뒤 양의 방향(동, 북)으로 적응적으로 이동.

이 알고리즘들의 약점은 적응성이 불균등하다는 점입니다. 예를 들어 West-First는 동쪽으로 가는 패킷에게는 완전한 적응성을 주지만, 서쪽으로 가는 패킷에게는 XY와 똑같이 결정적입니다.

Odd-Even Turn Model

Chiu(2000)의 Odd-Even 라우팅은 회전 금지를 열(column)의 짝/홀에 따라 다르게 적용합니다.

  • 규칙 1: 짝수 열에서는 동→북, 동→남 회전 금지.
  • 규칙 2: 홀수 열에서는 북→서, 남→서 회전 금지.

어떤 사이클이든 가장 오른쪽 열에서 동→(북/남) 회전과 (북/남)→서 회전이 같은 열에서 일어나야 하는데, 그 열은 짝수이거나 홀수이므로 둘 중 하나는 반드시 금지됩니다. 그래서 가상 채널 없이도 데드락이 없고, 방향에 따른 적응성 편중도 West-First보다 훨씬 고릅니다. 경로 탐험기에서 Odd-Even을 고르고 여러 출발/도착 쌍을 시험해 보세요.

무작위화: O1TURN과 Valiant

O1TURN(Seo et al., 2005)은 패킷마다 XY 또는 YX를 무작위로 고릅니다. XY와 YX를 섞으면 데드락이 가능하므로 두 종류의 패킷을 서로 다른 가상 채널 클래스에 분리합니다. 상태를 보지 않는(oblivious) 단순한 방법이지만 많은 패턴에서 처리량을 크게 높입니다.

Valiant 라우팅은 극단적인 방법입니다. 목적지와 상관없이 먼저 무작위 중간 노드로 간 다음, 거기서 목적지로 갑니다. 어떤 트래픽 패턴이든 균등 무작위 트래픽 두 번으로 바꿔 버리므로 최악의 패턴에 강하지만, 평균 경로가 두 배 가까이 길어져 평범한 트래픽에서는 손해입니다.

실전 비교: Transpose 트래픽에서의 XY vs 적응형

Transpose 패턴은 노드 \((x,y)\)가 \((y,x)\)로 보냅니다. XY 라우팅에서는 모든 패킷이 대각선 근처에서 회전해야 해서 일부 링크에 부하가 몰립니다. 아래 두 시뮬레이션은 같은 트래픽과 같은 주입률에서 라우팅만 다릅니다. 링크 색이 붉을수록 바쁜 링크입니다.

8장의 시뮬레이터 엔진을 사용합니다: 2 VC × 4플릿 버퍼, 4플릿 패킷, 라우터 지연 2사이클 + 링크 1사이클. 라우터 옆 파란 막대는 출발지 대기열 길이입니다. 주입률을 바꾸면 처음부터 다시 시작합니다.

핵심 정리

  • XY(차원 순서) 라우팅은 단순하고 데드락이 없지만 경로 다양성이 없어 특정 패턴에서 부하가 몰린다.
  • Turn model은 각 회전 사이클에서 하나씩 회전을 금지해 VC 없이도 데드락 없는 적응형 라우팅을 만든다. 단, 금지 조합에 따라 실패할 수 있다.
  • Odd-Even은 열의 짝/홀로 금지 규칙을 바꿔 적응성을 고르게 분배한다.
  • O1TURN·Valiant 같은 무작위화 기법은 상태 정보 없이 부하를 분산하며, 보통 VC 클래스 분리로 데드락을 피한다.

확인 문제

(1,1)에서 (4,3)으로 가는 최소 경로는 몇 개이며, XY 라우팅은 그중 몇 개를 쓸까?
Δx=3, Δy=2. 최소 경로 수는 \(\binom{5}{2}=10\). XY는 결정적이므로 1개만 씁니다. 경로 탐험기에서 '완전 적응형'을 선택하면 10개가 표시됩니다.
West-First 라우팅에서 목적지가 출발지의 북서쪽에 있다면?
West-First는 서쪽으로 가는 회전(북→서, 남→서)을 금지합니다. 따라서 서쪽 이동은 경로의 맨 처음에 모두 끝내야 하고, 북서쪽 목적지에는 단일 경로만 남습니다.
